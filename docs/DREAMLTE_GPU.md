# GPU on the Galaxy S8

The GPU is an ARM Mali-G71 MP20 of the Bifrost generation. This page holds what the port measured, what the kernel driver does, and the next steps.

## Hardware facts

| Item | Value | Source |
| --- | --- | --- |
| Register block | `0x13900000`, 0x5000 | Samsung device tree `mali@13900000` |
| Interrupts | SPI 60 (job), 61 (MMU), 59 (GPU) | same |
| Power domain | PMU `0x164840e0`, status `0x164840e4` | pmucal `g3d_on` |
| GPU clock | ACPM DVFS id 4 (`dvfs_g3d`), 260 to 839 MHz | ECT and device tree |
| CMU_G3D | `0x13800000` | pmucal |
| Coherency | none with the CPU (`COHERENCY_FEATURES` = 0) | run c30b |

## What the loader measured

Run c29 read the identity:

- `GPU_ID` = `0x60a00001`: product `0x6000` (G71), revision r0p0.
- `SHADER_PRESENT` = `0x17771777`: 20 shader cores.
- L2, tiler and job slots are present. `MMU_FEATURES` = `0x2830`.

Run c30b ran two jobs through the loader, with the MMU off:

- Identity mode (`ADRMODE_IDENTITY`) failed with `JS_STATUS` 0x42, `JOB_READ_FAULT`. Do not use it.
- Through our own 4-level AArch64 page tables the job finished: `JOB_INT_RAWSTAT` 1, status DONE, and the value landed in the mapped physical page. The same address without a mapping stayed 0.

The page tables use 4 KiB pages and the entry format of Linux panfrost: table entries with type 3, leaf entries with AF, read and write, outer shareable.

## The kernel driver

`iokit/Kernel/arm/S8Mali.cpp`, generated by `tools/dreamlte/apply-dreamlte.py` from `xnu/dreamlte/S8Mali.cpp`.

Milestone 2a, run on the phone on 2026-10-24 (log `logs/sweetlog-gpu2.txt`):

1. `s8gpu=1` enables the driver. Without the argument the driver does not start.
2. It maps the GPU and PMU registers and switches the G3D domain on if it is off.
3. It reads the PLL back and logs the GPU clock.
4. It soft resets the GPU, then powers L2, the shader cores and the tiler.
5. It builds one address space with its own page tables over a 64 KiB physically contiguous block.
6. It runs two WRITE_VALUE jobs on slot 0 and polls for completion. The first writes through a physical address, the second through a different GPU virtual address that maps to the same page.
7. It checks that a page which is not mapped stays untouched, then powers the GPU down.

Measured on the phone: the driver loaded, the GPU reported ID `0x60a00001`
r0p0 with 20 shader cores, all blocks came ready, and job 1 finished with
`RAWSTAT` 0x1 and the value `0xc0ffee11` in the mapped page. The first run
reported a failure only because it read the wrong status register; that is
fixed. Job 2 and the unmapped-page check run next.

The driver is not yet a user client. Mesa cannot talk to it.

## Next

1. Milestone 2b: an IOUserClient with the panfrost interface. The calls are `GET_PARAM`, `CREATE_BO`, `MMAP_BO`, `GET_BO_OFFSET`, `SUBMIT`, `WAIT_BO` and `MADVISE`.
2. Job completion through the job interrupt (SPI 60) instead of polling, plus a fence.
3. Fault handling through the MMU interrupt (SPI 61): log `AS_FAULTSTATUS`, `AS_FAULTADDRESS` and the job slot state, then reset.
4. Cache maintenance rules for buffers that the CPU writes and the GPU reads.
5. Mesa 25.0.7 with `panfrost` and OSMesa, and a Darwin `pan_kmod` backend.
6. CoreAnimation through its OpenGL ES backend. CoreAnimation renders in software today.

## Rules

- Do not report success with llvmpipe, softpipe or any CPU renderer.
- Measure the GPU temperature before you raise the GPU clock. The GPU TMU is `tmuctrl_2` at `0x10084000`.
- Keep the G71 errata workarounds from Linux panfrost: TMIX_8463, TMIX_8438 and T76X_3953.
